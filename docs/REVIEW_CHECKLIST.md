# Review checklist

Use this checklist for every on-demand Discord audit.

- [ ] Read **all accessible** new messages in Bug Reports and relevant follow-up replies
- [ ] Read **all accessible** new and archived Suggestion Forum threads and replies
- [ ] Inspect attached screenshots when accessible; do not invent their contents
- [ ] Compare every candidate against **open and closed** GitHub Issues
- [ ] Distinguish one issue mentioned repeatedly from separate root causes
- [ ] Capture the original Discord deep link and report date if accessible and permitted
- [ ] For bugs: actual / expected / steps / version / affected mode and item IDs when known
- [ ] For suggestions: player problem / proposed solution / impact / limitations / refinement
- [ ] Record priority as a recommendation, never developer commitment
- [ ] Confirm privacy/publication permissions before adding names, quotes or media to public GitHub
- [ ] Create or update only supported Issues
- [ ] Update [BOARD.md](../BOARD.md) consistently with statuses backed by evidence
- [ ] Add a dated entry to [AUDIT_LOG.md](AUDIT_LOG.md) describing real coverage
- [ ] Summarize created / updated / merged / still uncertain to the moderator

## Editorial conventions

- Ticket titles: `[BUG] ...`, `[SUG] ...`, `[META] ...`.
- Main sections: Summary, Source, Reproduction or Use Case, Actual/Expected or Proposal, Evidence, Impact, Verification, Recommended priority, History.
- Leave unknowns as *Unknown / not provided* rather than guessing.
- Suggested statuses: Needs Review, To Do, In Progress, Testing, Done.
- Suggestion decision: Proposed, Needs Discussion, Accepted, Rejected, Duplicate. These are separate from progress status.
- Summarize/sanitize internal Discord discussion before publishing; never expose passwords or personal details.
